Mac · USB drive docks · Drive health

Check a hard drive's health through a USB dock.

Every hard drive keeps a health report on itself: hours used, bad spots, temperature. A Mac can't read that report when the drive sits in a USB dock or enclosure, and the apps that can ask you to lower the Mac's security first. usbsmart reads it with the Mac's security left alone.

Get it View the source

Free and open source (MIT license). It only reads the report. It cannot erase or change a drive.

What it shows

The numbers that say whether to trust a drive.

The full table has up to 30 rows. These are the ones to read first. Under the table, the tool lists any number that looks wrong and says in plain words what it means.

The verdict

PASSED or FAILED, judged against the limits the drive's maker set for each number.

A number at or past its limit is marked FAILING_NOW. Copy the data off that drive before doing anything else with it.

Bad spots

Worn-out parts of the disk

Spots that stopped holding data and were swapped for spares, and spots waiting to be swapped. Both should read 0. A count that keeps climbing means the drive is on its way out.

Age

How much life it has had

Hours switched on and the number of times it has been powered up. The drive above shows 87,079 hours and 2,264 power-ups.

Heat

Temperature

In Celsius, right now. Some drives also report the hottest and coldest they have been.

Cable trouble

Garbled transfers

A count of data that arrived damaged between the drive and whatever it was plugged into. Above 0 usually points at a cable or connector, with the drive itself fine.

How it works

One layer of the disk stack is replaced.

USBSmartDevice subclasses IOUserSCSIPeripheralDeviceType00 from SCSIPeripheralsDriverKit. Its kernel half is Apple's own disk driver, so reads and writes never pass through this project's code. The subclass adds UserSendCDB, which carries ATA PASS-THROUGH (16) to the bridge.

IOUSBHostInterface                    the dock's USB interface
  IOUSBMassStorageDriver              Apple's USB mass-storage driver, unchanged
    IOSCSIPeripheralDeviceNub         one SCSI logical unit
      USBSmartDevice                  in place of Apple's IOSCSIPeripheralDeviceType00
        IOBlockStorageServices
          IOMedia                     disk9
Matching

Outranking Apple's driver

Both personalities match Peripheral Device Type 0. The SCSI family adds a personality's IOProbeScore to its own ranking (clamped below 5000), so 1000 outranks Apple's personality, which has none.

Matching

Exact bridge matches

bridges.json generates 12 exact USB vendor/product matches, each restricted through IOParentMatch -> IOPropertyMatch. The same SAT command code serves all of them. There is no wildcard match for every USB disk.

Signing

No request to Apple

Three entitlements: driverkit, driverkit.family.scsicontroller and driverkit.allow-any-userclient-access. Xcode's automatic signing adds all three to a development profile. No USB transport entitlement, because the driver never opens the USB interface.

Found on the way

A zero in Apple's helper

SMART_Get_Identify_Data on DriverKit 27.0 was building 85 08 0e 00 00 00 00 … ec 00: ATA sector count 0, while t_length says the count field holds the transfer length. The driver sets the count to 1, the form smartmontools sends, before the command goes out.

Decoding

smartctl, fed a recording

smartctl can replay a recorded session: given - as the device, it reads smartctl -r ataioctl,2 debug text on standard input and decodes it as if it had talked to the drive. usbsmart --smartctl writes the pages it read in that format and pipes them in.

No hardware needed

Decoder check

tests/decoder.sh builds a made-up set of pages with valid checksums, decodes them and diffs the result against tests/expected.txt. It runs in CI after the unsigned build.

Read-only

Five commands, all of them reads.

Each command is built by Apple's helpers, then checked byte by byte against this list before it is sent (IsAllowedCDB in Driver/USBSmartDevice.cpp). A command that fails the check comes back to the tool unsent, with its 16 bytes. The drives this was written for may hold the only copy of someone's data.

ATA PASS-THROUGH (16), opcode 85h
  • 01
    IDENTIFY DEVICEECh. Model, serial, firmware, capacity, sector sizes. 512 bytes in.
  • 02
    SMART READ DATAB0h / D0h. Up to 30 attributes of 12 bytes each. 512 bytes in.
  • 03
    SMART READ THRESHOLDSB0h / D1h. The failure threshold for each attribute. 512 bytes in.
  • 04
    SMART READ LOGB0h / D5h. One sector of one log: directory, error log, self-test log.
  • 05
    SMART RETURN STATUSB0h / DAh. No data, the answer comes back in the LBA registers.

macOS itself still mounts any volume it recognises on the disk, read-write, as it does without the driver.

What works

One dock tested so far.

Tested on a MacBook Pro (M2 Max) running macOS 27.2.1, with a Sabrent USB 3 dock holding a 500 GB WD drive and then an 8 TB Seagate.

Works

Connect a drive and open USBSmart. Select it in the sidebar to read its health report.

The app shows the drive model, capacity, temperature and SMART attributes. Click Refresh to read again. The command-line tool is also included.

Works

The full report

Add --smartctl and the free smartctl tool decodes the same data with its database of drive models, including the drive's own error log.

One caveat

The verdict is worked out

This dock does not pass along the drive's own one-word verdict, so PASSED or FAILED comes from comparing each number with its limit. smartctl does the same in that case.

Untested

Other docks

Twelve bridge IDs are listed across VIA Labs, ASMedia, JMicron and LucidPort. The VL715 is verified; the other 11 are candidates based on the smartmontools SAT database. They still need testing with this macOS driver. Driver setup shows the compatibility list.

Not supported

What it can't read

NVMe SSDs (the stick-shaped kind) keep a different report. Intel Macs are out: the driver is built for Apple silicon only.

Security

Your Mac's settings stay as they are

No kernel extension and no Reduced Security, and System Integrity Protection stays on. You approve the driver once in System Settings, with the same switch any driver uses. The drive still shows up in Finder and Disk Utility as before.

Get it

A public download needs Apple’s approval.

The app now displays the drive list and health report itself. The DriverKit distribution request has been submitted to Apple. Once approved, the app can be signed and notarized for download. Until then, the build instructions below are for developers using their own Macs.
